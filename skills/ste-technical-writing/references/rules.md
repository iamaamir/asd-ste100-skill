# Issue 9 writing rules — independent paraphrased navigation map

**Source:** ASD-STE100, Issue 9 (2025-01-15), Part 1. This is an operational index, **not a reproduction of the standard**. Consult the official PDF for complete language, exceptions, definitions and examples. The 53 numbered rules are in nine sections. Page numbers in the source use identifiers such as `1-5-1`.

## 1 — Words (14 rules; Part 1, Section 1)

| Rule | Review obligation |
| --- | --- |
| 1.1 | Restrict vocabulary to approved dictionary entries and valid technical terms. |
| 1.2 | Check the dictionary-approved part of speech for each ordinary word. |
| 1.3 | Check the particular approved *meaning*, not just the spelling. |
| 1.4 | Use only permitted inflected/comparative forms. |
| 1.5 | Apply an appropriate category when accepting a technical noun. |
| 1.6 | Treat an unapproved word as valid only inside a legitimate technical noun, or under the separate technical-verb permission of 1.12. |
| 1.7 | Do not turn technical nouns into action verbs. |
| 1.8 | Check technical noun approval within the applicable organization, industry, or field. |
| 1.9 | Favor understandable, concise technical noun names when there is a choice. |
| 1.10 | Reject slang, region-specific jargon, and informal local terms. |
| 1.11 | Use one stable name per item/concept. |
| 1.12 | Permit category-specific technical verbs only in their correct technical context; prefer dictionary verbs when sufficient. |
| 1.13 | Do not use a technical verb as a noun. |
| 1.14 | Normally write with American English spellings, subject to applicable official directives. |

**Issue 9 detail:** The standard uses *technical noun* (not the older *technical name*) and *technical verb*. Domain categories and their boundaries matter. Familiar software verbs may be legitimate technical verbs in a UI context yet not valid in everyday prose. Do not create a universal banlist or allowlist for these terms.

## 2 — Multi-word nouns (2 rules; Section 2)

| Rule | Review obligation |
| --- | --- |
| 2.1 | Keep ordinary noun groups short: up to three words. |
| 2.2 | Keep established longer technical item names intact when required by their official form. |

## 3 — Verbs (7 rules; Section 3)

| Rule | Review obligation |
| --- | --- |
| 3.1 | Confirm dictionary-listed verb forms before use. |
| 3.2 | Limit constructions to the prescribed forms and basic tenses. |
| 3.3 | Past participles may be used adjectivally under the rule. |
| 3.4 | Avoid composite constructions made with auxiliary verbs. |
| 3.5 | Do not use a verbal `-ing` form; the technical noun/noun-modifier exception is important. |
| 3.6 | Prefer active voice. Descriptive passive is conditional on an unknown agent. |
| 3.7 | Express an action with a suitable approved verb instead of a noun-heavy construction. |

**Allowed tenses/forms in 3.2:** infinitive, command, simple present, simple past, simple future, and adjectival past participle. Consult the source for details.

## 4 — Sentences (5 rules; Section 4)

| Rule | Review obligation |
| --- | --- |
| 4.1 | Keep sentence structures direct, unambiguous, and readable. |
| 4.2 | Preserve necessary grammatical words and do not contract them. |
| 4.3 | Use vertical lists to break up difficult material. |
| 4.4 | Explicitly link related ideas with suitable connecting terms. |
| 4.5 | Supply appropriate articles/demonstratives when a noun needs one. |

**Issue 9 detail:** Rule 4.5 is the rule formerly located in section 2 as old Rule 2.3. Use the new numbering.

## 5 — Procedural writing (5 rules; Section 5)

| Rule | Review obligation |
| --- | --- |
| 5.1 | At most 20 words in each instruction sentence, including safety instructions. |
| 5.2 | Typically one command per sentence; simultaneous work is a defined exception. |
| 5.3 | Direct the reader with imperative verb forms. |
| 5.4 | Put a prerequisite condition first, followed by a comma and the required command. |
| 5.5 | Keep notes informational, not a place to hide new instructions. |

## 6 — Descriptive writing (6 rules; Section 6)

| Rule | Review obligation |
| --- | --- |
| 6.1 | Present information in a manageable sequence. |
| 6.2 | Build logical structure with recurring key terms and clear links. |
| 6.3 | At most 25 words in each descriptive sentence. |
| 6.4 | Group related material into paragraphs. |
| 6.5 | Restrict each paragraph to a single topic. |
| 6.6 | At most six sentences in one paragraph. |

## 7 — Safety instructions (3 rules; Section 7)

| Rule | Review obligation |
| --- | --- |
| 7.1 | Use the risk-level label recognized for the relevant application. |
| 7.2 | Start with an explicit protective action or relevant condition. |
| 7.3 | Explain the harm or damage that can result. |

**Safety precision:** In the aerospace context, warnings relate to personal injury/death and cautions to damage of equipment or objects. Other domains may classify hazards differently; check local policies and preserve legal requirements.

## 8 — Punctuation and word count (7 rules; Section 8)

| Rule | Review obligation |
| --- | --- |
| 8.1 | Use standard punctuation other than semicolons. |
| 8.2 | Connect related expressions with hyphens as specified. |
| 8.3 | Restrict parenthetical material to supported uses. |
| 8.4 | With vertical lists, count the list introduction and each subsequent item as separate sentences after the colon. |
| 8.5 | Count a parenthetical span as one word in its containing sentence and count its own contents separately. |
| 8.6 | Count listed indivisible items as one word: numerical values, value/unit pairs, acronyms, identifiers, quotes, designated titles/labels, certain proper names. |
| 8.7 | Count a hyphenated compound as a single word. |

**Counting caveat:** For professional exact counts, an agent must understand whether a span is a quoted placard, a title, an ordinary phrase, or a true proper name. Generic tokenization cannot decide this reliably.

## 9 — Writing practices (4 rules; Section 9)

| Rule | Review obligation |
| --- | --- |
| 9.1 | Restructure the grammar rather than blindly swapping words. |
| 9.2 | Use approved words only in their approved usage. |
| 9.3 | Do not build phrasal verbs from ordinary words. |
| 9.4 | Keep terminology, grammar, and style stable across the document. |

The section also contains **eight general recommendations**: `GR-1` through `GR-8`, dealing with use of *that*, *with*, pronouns, *this*, false friends, Latin abbreviations, inclusive language, and possessives. These are **recommendations**; do not mislabel them as numbered rules.
